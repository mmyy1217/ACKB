# CCEC 唯一 op 与接口层级

CCEC Builtins 目录限定在 intrinsic / builtin 层。op 的唯一身份是完整 `__builtin_cce_*` 标识符，而不是短函数名、头文件、声明行或硬件 opcode。同一 builtin 的不同 intrinsic 别名和来源归入同一 op；不同 builtin 即使语义相近也不合并。

## 依据与分类

同版原始 catalog 保持不变，5,714 条接口记录及旧 ID 全部保留。`ops.json` 由该快照确定性派生，绑定 catalog 与生成器哈希。当前得到 4,353 个唯一 op：身份依据为显式 `clang_builtin_alias` 属性，或函数体中宏展开后的完整 builtin 调用标识符。后者只证明源码引用该 builtin，不能证明所有分支都调用它，也不能给出完整参数约束。

原记录分为 1,525 条 intrinsic 入口声明、4,182 条带实现的封装、7 条待解析入口。记录数不是 op 数。一个封装可引用多个 op，一个 op 可被多个封装引用；带实现的简单转发函数也属于封装。非接口的类型、宏定义和辅助记录仍在配套定义中。

337 项关联缺口和 207 个仅文本 builtin 候选单列，不按短名称推断，不将宏拼接前缀当完整 builtin。这里的全量是当前接口记录的层级覆盖，不是编译器内部全部 builtin 或硬件 ISA。

## 关系与证据

关系包括入口声明的显式 alias、函数体内直接 builtin 调用、完整 `__cce_*::name` 引用。完整限定名只在对应 alias 映射唯一时关联；不靠同名、目录名或参数名猜测。每条边保留来源记录 ID、预处理条件；原始记录保存签名、定义、宏来源、位置及文件哈希。

函数体内的运行时或模板分支保留在源码，未解析为精确执行条件；当前边是有方向的词法引用，不是已解析重载的完整调用图。未限定名调用、间接封装链和任意 C++ 模板求值不自动解析。没有找到关联不意味着没有调用。

950 的 `::copy_gm_to_ubuf`（记录 `41997fe279e39ece787b`）在 `__NPU_ARCH__ == 3510` 分支处理参数后引用 `__cce_scalar::copy_gm_to_ubuf_align_v2`，关联 `ccec_op___builtin_cce_copy_gm_to_ubuf_align_v2`。它不关联同名的 `ccec_op___builtin_cce_copy_gm_to_ubuf`。后者自己的入口是记录 `13c808703f3d6b63c4c4`。

## 参数形式与架构

有类型 alias 声明按保留参数名和默认表达式的词法签名组织，重复的相同形式合并来源；页面称“有类型声明形式”，不声称 C++ 重载解析完成。`...` 不是完整参数签名，显示未确定；函数体调用与上层封装参数不能冒充 builtin 的完整签名。

op 架构筛选仅汇总显式入口声明条件：任一符合即“至少一个入口声明符合”，否则有未知或缺少声明即未知，全部排除才是当前声明条件排除。每条来源条件仍可展开。**不继承调用者条件，不继承旧名称级 AscendC 引用矩阵。** 旧源码证据只在原始记录详情中作为带歧义的辅助线索展示。编译、运行和设备支持保持未验证。

弃用证据仍归属具体来源声明，未把某个别名的弃用提升为整个 builtin 弃用；主 op 视图禁用旧声明级弃用及名称源码证据筛选，原始记录视图保留它们。

## 网页与 AI

网页“底层 op”每个 builtin 一行；入口声明、上层封装、待解析入口分层浏览。“原始记录”是保留原审计口径的附属视图，其名称组及声明数不用于 op 计数。详情可从 op 进入具体入口或调用者，再沿有向关系返回 op。旧记录深链接自动进入对应层。

JSON 导出包含唯一 op、关联边、相关原始来源记录及完整文件清单，避免只有悬空来源 ID。主列表显示 op 数；形式数未确定时显示破折号，不用来源数冒充重载数。

AI 主入口为 `query.py ops`，按名称或 builtin 查询；`get / support / relations` 接受 `ccec_op_` ID，返回 `ackb.ccec-ops.query.v1` 信封。`schema --layer ops` 给出信封规范。大型调用关联用 `relations` 分页；原始签名和实现仍用旧记录 ID 查询 `get / evidence`。原有 `search` 保持声明层兼容，不代表唯一 op 搜索。执行命令统一放在根目录 AGENTS.md。

## 950 / A5 双层阅读（当前默认）

页面固定 Huawei Ascend 950PR_9579 / NpuArch 3510，不提供 CCEC 架构选择。顶栏切换“CCEC 编程接口 / CCEC Builtins / PTX”；CCEC 默认调用接口层。接口以命名空间与名称唯一分组，368 个接口至少有一个声明条件符合（357 个封装及 11 个已追踪的搬运直连入口）；191 个只有未知声明条件，通过“显示待确认”加入，共 559 个；66 个全部排除，不进入主目录。

两层默认均只显示符合声明条件的记录，不把它称为设备支持。Intrinsic 按入口声明独立判断，不继承封装条件。关系跳转到未知条目时显式打开待确认开关；排除的来源只作为单条证据查阅，不加入主列表。深链接中的旧芯片参数不会改变 950 范围。

左栏仅保留指令族。原始声明、配套定义与知识解释从详情或“说明 / 覆盖”进入，不另设侧栏导航。上下层可互跳；导出带固定目标、层级、待确认开关、选中关系及其来源记录。原数据与多架构 CLI 证据仍保留，页面只使用 950 场景。

AI 默认入口 `interfaces` 同样返回 950 的 368 个接口，`--include-unknown` 返回 559 个。接口 ID 可用 get 查询，各来源记录保存独立条件。`ops` 默认 950 且条件符合；`--condition possible` 加入未知项，显式架构参数仍供数据审计使用。旧声明查询保持兼容。

## 参数选择与搬运路径

Intrinsic 详情顶部恢复原生参数形式选择器，直接显示当前签名、逐项参数和来源链接。无精确签名时明确显示未确定；关联封装的参数使用独立选择器，不能替代 builtin 签名。两种选择均保存在深链接中。当前快照每个 builtin 至多一个有类型声明形式；之前看到的多个参数版本主要属于封装声明，不应按短名称拼成 builtin 重载。

两层列表与详情均保留 GM → UB、GM → L1 等路径信息，支持 GM2UB / GM2L1 搜索；左栏只保留大类。默认条件筛选不变；无匹配封装的路径提供“显示待确认”和“查看同路径 Intrinsics”，不推断缺失即不支持。详见 [分类依据](classification.md)。
