# 执行流程

执行命令统一维护在 [AGENTS.md](../AGENTS.md)。本文件记录流程、产物和证据规则。

## 1. 固定来源

定位原始安装包并计算 SHA-256；保存版本信息、文件清单和关键文件哈希。独立提取到工作区产物目录，不覆盖现有工具链。仅有安装目录时明确记录来源待核验，不宣称已核对原包。

## 2. 提取与整理

按 [扫描范围](scope.md) 盘点并追踪依赖。正则用于发现，结构化解析用于提取多行声明、模板、宏、重载与 alias。保留原始条件编译分支，不能仅解析某个目标预处理后的可见子集。

每次运行产出来源清单、接口数据、配套定义与未解析报告。排序和标识应稳定，相同输入应能重复生成相同语义数据。AI 负责辅助分类与解释，所有补充结论须附来源或标为待确认。

## 3. 数据校验

校验记录字段、唯一身份、来源位置、重复声明及类型关联。用覆盖不同声明形式的实际样本检查提取准确性；解析失败不可按成功计数。对原始声明与生成结果抽查，覆盖统计必须可以复算。

## 4. 生成网页

使用原生 HTML / CSS / JavaScript，从结构化数据生成可离线打开的页面，不依赖 CDN、在线字体或远程服务。选择兼容本地文件打开的数据载入方式。

页面以紧凑列表为主：搜索、筛选、接口详情、来源与实验记录。支持键盘操作、可见焦点、长签名阅读、空结果及数据缺失状态。默认浅底，颜色用于状态与交互；证据等级必须有文字表达。

实际在浏览器中检查桌面和窄屏布局，以及搜索、组合筛选、详情展开、链接定位与离线打开。真实数据未就绪时明确标注空状态，不使用伪造接口和实验结果。

## 5. 补充验证

优先选择 copy/DMA、FP8/FP4、MX/SF 与同步相关接口，逐步扩展。实验单独记录设备、工具链版本、完整命令、样例和输出。编译通过与运行正确分别记录，性能结论必须有实际测量。

设备相关实验遵循上层工作区的远程目录、设备和资源规则；执行前核对环境，不因本项目目标版本而擅自升级远程工具链。

## 产物组织

当前仅初始化文档；以下目录在对应实现阶段创建：

| 位置 | 用途 |
| --- | --- |
| `scripts/` | 提取、校验和网页生成工具 |
| `data/` | 版本化结构数据、来源清单及可追溯解释 |
| `web/` | 网页源码与资源 |
| `tests/` | 必要的提取与数据校验样例 |
| `dist/` | 可离线阅读的生成页面，本地构建产物 |

原始包、大型日志、IR 和实验中间文件保存在上层工作区 `work/experiments/cce-ops/<version>/<run>/`，保留原位。仓库内记录稳定来源标识与相对引用，机器绝对路径仅用于本地命令；不将完整 Toolkit 或设备库提交入库。

## 阶段交付

检查变更、运行该阶段适用的验证并记录结果；更新路线中的真实状态，保持 README 的展示与实际能力一致。阶段完成后本地提交，外部发布遵循 AGENTS.md 的授权边界。
