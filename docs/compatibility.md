# 架构、芯片与弃用证据

本阶段按每条声明或重载核对条件，不将接口名称、头文件可见或编译成功等同于芯片运行支持。

## 当前能力

- 构建时从原始记录生成架构条件场景；分别命名 `__CCE_AICORE__`、`__NPU_ARCH__` 和 `__DAV_*`，不混用编号体系。
- `targets.json` 保存本版本安装目录中 74 个芯片型号、14 个 NpuArch 值及 CCEC 核目标配置。每个条目带配置路径、节名与 SHA-256。它们尚未与原包核对，不继承 23 个头文件的原包验证状态。
- 选择芯片采用配置的 NpuArch 值。核目标只展示原始配置；尚未建立各核完整的编译器预定义宏环境，不能据此筛掉核专属接口。
- 三值求值：条件符合、条件排除、待确认。只替换场景中明确给出的宏；其余宏保持未知，而不是当作未定义或零。支持逻辑、比较、括号与 defined；未支持的语法返回未知。头文件保护宏单独排除。选择目标后默认保留符合或待确认项，可查看明确排除项。
- 结果仅针对声明自身条件，不覆盖入口包含路径、函数体分支、模板实例化与编译器内部约束。条件符合不是已证明声明可见，更不是设备支持。
- 弃用分为有标记、条件性标记与未检出。保留 `DEPRECATED_AFTER_V210` 等宏的条件定义；未检出不代表未弃用。暂无首次弃用版本和逐接口替代关系，不能由 legacy 文件名推出这些结论。
- 筛选作用于重载，名称组、进度、详情与 JSON 导出同步。深链接保存目标和条件结果。平台元数据与派生分析保存在离线 HTML 及导出的 JSON 中；原始 catalog 保持不变。

## 版本差异

`compare.py` 按命名空间、名称和形式比较重载集合，报告新增、移除，以及签名、条件和弃用标记变化，并附提取器修订号。需要同等提取口径的两个真实版本；现在只有一个版本，不能显示真实历史变化或声称首次弃用版本。原始提取器仍锁定本轮 weekly，新版本提取需要单独核对元数据与资源布局。

## 下一步依赖

1. 核验平台配置的原包来源，并建立芯片、核目标到完整预定义宏环境的映射。
2. 补充包含路径与宏条件传播，核对编译器内部 builtin 候选；二进制字符串不能直接计为可调用接口。
3. 按目标架构做最小编译探针，保存诊断与工具链版本；远程实验遵守工作区资源授权规则。
4. 提供第二个版本的数据后运行差异分析，再开放网页版本切换与历史比较。
