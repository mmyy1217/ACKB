# 950 搬运入口与观测调用形式

## GM → L1 为什么曾经为空

旧目录只收录有函数体的 CCEC 封装。`::copy_gm_to_cbuf` 在旧宏分支下，当前只给 NpuArch 3510 的环境无法判定其 `__DAV_L311__ / __DAV_L311_EFF__` 条件，仍为未知。950 的 AscendC 源码则直接使用 `copy_gm_to_cbuf_align_v2`、`copy_gm_to_cbuf_multi_dn2nz`、`copy_gm_to_cbuf_multi_nd2nz`、`copy_gm_to_cbuf_v2`、`load_gm_to_cbuf_2dv2`、`load_gm_to_cbuf_2dv2_s4`。这些名字在固定资源头文件中有显式 builtin alias，不能因为没有已知的同名封装就从调用接口目录漏掉。

当前接口目录保留原有 357 个条件符合的封装，并补充 11 个已追踪的搬运直连 alias 入口，共 368 个；191 个待确认封装和 66 个排除封装判定不改写。包含待确认为 559 个，不能把增加的 11 个解释为新增硬件能力。Intrinsics 的 4353 / 1514 身份和条件统计不变。

## 证据范围与身份

`a5-calls.json` 由固定版本 `9.3.0~weekly.20261104.01` 的 8 个 AscendC 实现文件提取，来源哈希匹配已有源码快照和原包校验证据。先解析明确的 `__NPU_ARCH__ == 3510` include 分支，再解析相对路径及 `asc/`、`asc/include/` 根下的 include；不把目录名本身当成架构证明。每个文件保存完整选择路径及各跳源文件哈希。

本轮范围为名称明确带 GM / UB / L1 端点的搬运入口，在经选择路径到达的 `dav_3510` / `npu_arch_3510` 实现中检索。256 个候选全部解析为调用，覆盖 12 个入口，未解析 0 项。此数字只覆盖这个有界范围，不宣称整个 CCEC 或所有存储层级均已完成参数恢复。

调用通过唯一 alias 名称关联原始入口记录和 builtin ID，保存 `unique_alias_spelling_not_cpp_overload_resolution`：没有运行 C++ 名字查找、重载解析或编译器。原有 builtin 身份仍由显式 alias 确立；新增调用证据不改变 builtin 的架构支持判定。

默认接口目录补充满足以下条件的原始 alias 记录：有本轮 3510 条件符合的调用；自身入口声明条件符合 3510；当前没有同名条件符合的封装。身份仍为命名空间 + 名称，保留原始记录 ID；界面标注“直连”。未知开关可能同时显示不同命名空间的旧封装，不能合并为同一个 C++ 符号。高层 AscendC 函数仅作为调用证据，不新增为 CCEC 编程接口。

## 参数恢复的含义

每个调用保存参数个数、实参表达式、调用方签名、源码位置、预处理条件和局部核 / 模板分支保护。表达式类型来自调用方参数、显式 cast、局部声明或字面量；无法安全确定的计算表达式保留未知，不做 C++ 类型推导猜测。

例如 `asc_copy_gm2l1_align` 在 `ASC_IS_AIC` 分支传入 11 个实参；可恢复地址类型、搬运次数 / 长度、填充参数、缓存模式、源 / 目标步长的顺序。`0` 的观测类型是 int，不因此断言 builtin 对应形参是 int。c_api 与 basic_api 调用可以使用不同的实参类型，因此必须保存各自来源。

前两个地址实参与名称中的目标 / 源空间做交叉核对，当前 256 处均一致。这支持这些路径的源码分类，但不证明完整内存语义或设备支持。动态条件、核宏和模板条件保留原文，不转成验证结论。

网页选择“950 源码调用形式”查看签名表达式与参数表；“Intrinsic 参数形式”仍专指有类型的入口声明。形式按观测表达式和类型依据合并展示，全部调用来源保留，可通过深链接恢复选择。JSON 导出和 CLI `calls` 提供相同证据，编译、运行、正式形参规范均标记未验证。

## 校验与查询

执行命令在 AGENTS.md。构建 / 查询读取提交的快照，无需 CANN。`validate` 核对 catalog 和源码快照哈希、调用 ID 唯一性、参数数量、候选覆盖及选择路径；重新提取还核对安装目录中实现及选择器文件哈希。未知身份、错版本或不一致快照明确报错。

CLI `calls <入口名 / op ID / 原始入口记录 ID>` 分页返回调用和来源证据，`get <ccec_call_ID>` 返回单条。`get <op ID>` 附调用 ID 和查询入口。该查询固定 950，不能用来回答其他架构的参数规范。
