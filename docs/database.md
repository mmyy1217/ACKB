# AI 查询数据库规范 v1

## 共用数据与边界

版本化 `catalog.json` 是原始声明与来源记录，旁边的 `targets.json` 是平台配置证据。`scripts/database.py` 为 Python 查询层与 HTML 构建提供共同加载入口；不需要数据库服务或第三方运行依赖。CLI 不启动编译器，不访问网络，不操作安装目录。

这是一份源码接口数据库，不是 CCEC 内部 builtin 全集或硬件 ISA 数据库。查询结果中的未知、未解析与未验证属于数据本身，不应由使用者自动补成支持结论。

## 身份与粒度

| 字段 | 身份依据 | 稳定范围 |
| --- | --- | --- |
| `symbol_id` | 接口形式、命名空间、名称 | 不含版本、文件、行号与条件，可跨快照关联同名接口 |
| `variant_id` | symbol 身份与完整签名 token 序列 | 排除 token 间空白差异；参数、模板、修饰标记等变化会生成新身份 |
| `id` / `record_id` | 原提取器的版本、来源、签名与条件身份 | 某次版本快照中的声明出现，用于精确证据引用 |

symbol / variant 使用规范化 JSON 输入的 SHA-256 前 24 个十六进制字符，并有 `sym_` / `var_` 前缀。身份计算不依赖文件位置或启发式指令族。网页原深链接仍用原记录 ID，因此不会因新身份层加入而失效。

**variant 是词法签名变体，不是完整 C++ 类型系统归一化后的重载。** 参数改名、默认参数或弃用修饰变化可能产生新 variant。相同名字在相同命名空间的来源会归为同一 symbol，数据库仍完整保留所有来源记录，不以聚合代替语义等价证明。重命名的跨版本关联需要额外证据，不能自动猜测。

## 实体与关系

- 版本：数据集的精确 CANN 版本；本轮只存在一个真实版本。
- symbol：接口形式、命名空间与名称组成的导航身份。
- variant：完整词法签名，所属 symbol。
- 声明记录：variant、原始条件、来源范围、是否宏生成；不合并条件分支或重复来源。
- 目标：芯片配置、架构场景与可选核目标。芯片映射使用 NpuArch，核目标仅检查是否在配置中，`core_evaluation=unverified`，不增加未经证明的核宏。
- 证据：版本、资源目录、相对文件、行号范围、文件 SHA-256、限定范围的原包校验状态。宏生成声明同时提供宏来源哈希。
- 关系：`builtin_reference` 仅表示头文件中的关联引用；`call_name_reference` 提供同名 symbol 候选，但不声称已完成命名空间查找、模板或重载解析。
- 语义：参数含义、对齐、副作用、同步要求目前为 `null`，总状态 `unreviewed`；不按名字生成硬件语义。
- 实验：目前为空数组。编译、运行、性能分别标记 `unverified`；将来加入实验必须绑定版本、目标、variant、命令、样例与结果证据，不能只修改状态文字。

## 查询协议

返回协议标识为 `cce-ops.query.v1`，机器结构见 [JSON Schema](../schemas/query-v1.schema.json)。Schema 定义分页封套、记录及证据结构；`schema` 命令直接返回 Schema 文档。

成功响应包含版本、操作名、catalog 哈希、提取器与分析器修订及哈希、限制、总记录数、偏移、结果、下一偏移与是否未返回全部结果。数量是声明记录数，不能解释为硬件指令数。排序固定为名称、variant、记录 ID；同一数据集与条件下分页可重复。

默认每页 10 条，最大 50 条；默认输出预算 24,000 字符，最大 100,000 字符。预算不足时减少当前页条数并提供下一偏移，不截断签名；单条结果超过预算时返回明确错误。证据的 `representation` 区分原始来源片段与提取后的声明；选择 definition 时可能是宏展开结果，不能当作原文件逐字引用。证据正文可以截断，返回完整长度与 `text_truncated`，使用者需要增加预算再取，不能把不完整正文当全文。

空查询结果返回成功、零条结果；错误身份、目标、选项或损坏数据返回 JSON 错误并以退出码 2 结束。`--help` 为人类可读帮助。常规 stdout 只输出一个 JSON 文档，便于管道消费。

## 查询能力

`info` 查询覆盖与限制；`targets` 列出芯片及宏场景；`search` 支持名称、签名片段、builtin 反查、形式、架构条件和弃用筛选；`get` 接受 symbol、variant 或记录 ID；`relations` 提供带来源的关联引用；`evidence` 按精确记录 ID 获取来源文本。

AI 查询不沿用网页的默认芯片。未明确选择目标时，条件结果为 `not_evaluated`。指定核目标不会过滤出所谓“该核支持接口”；只有声明条件的符合、排除或未知判断。用户要求已验证可用性时，应报告目前没有实验结果。

这是可由 CLI、后续 MCP 或其他调用方复用的 Python 查询层；当前未新增 MCP 服务，也未引入额外数据副本或在线后端。

## ACKB 后端扩展

本文件描述的 CCEC 声明协议及稳定 ID 保持兼容。新增 PTX 和 CCEC 主题/builtin 索引使用独立的 `ackb.knowledge-query.v1` 信封，范围与字段见 [知识索引](knowledge.md)。两种协议不能混用支持状态或假定 ID 可互换。

## 支持证据查询

新增 `support` 操作，身份和 chip/core 参数沿用 `get`，返回声明条件、缺失宏、被忽略的声明保护宏、AscendC 名称引用、所在核保护块与入口包含边。引用只匹配名称，不完成重载解析；当前 support 固定为 unverified。信封保留 cce-ops.query.v1，新增 support_evidence_sha256。独立追踪工具支持引用分页及全部 74 个芯片配置的条件与源码证据矩阵；static-support.json 另保存全量架构判定、来源哈希与缺失宏审计，support-package.json 保存 1,608 个扫描源码文件的原包校验。命令见 AGENTS，边界见 [支持证据追踪](ccec-support.md)。
