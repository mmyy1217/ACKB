# PTX 阅读层与 B300

目标是先理解 PTX 自己的模型，再讨论与 Huawei Ascend CCEC 的设计差异。7 个阅读层次是编辑组织，不声称是 NVIDIA 官方硬件单元分类：全景、执行、存储、基本指令、协作与异步、矩阵、完整程序。跨后端比较放在各主题末尾，不建立伪造的一对一指令映射。

## 数据与来源

- `learning.json`：15 个原创中文主题、18 个术语、16 个特定指令条目的入门解释，附官方锚点、范围与验证状态。示例解释只覆盖显示的操作数形式，不外推到同名其他精度的条目。
- `syntax.json`：从固定 PTX ISA 9.4 / CUDA archive 13.4.3 HTML 中提取 296 个 Syntax 块，覆盖全部 221 条指令。每块保存内容哈希和来源锚点，整体绑定原手册哈希。重建命令见 AGENTS。
- `device.json`：NVIDIA 官方 MIG 支持表把 B300 标为 Blackwell / CC 10.3；记录 URL、观察日期及页面哈希。未做设备查询。
- 既有 `source.json`、`scan.json` 和原始索引中的 `sm_89` 保留历史快照。运行时评估由 `ptx_targets.py` 生成，CLI 与网页共用；历史统计不得解释为当前 B300 统计。

完整手册描述不入库。条目可能有完整语法但还没有中文逐操作数解释；界面明确提示缺口。三份原创程序分别演示向量加法、单 CTA 256 元素求和、16×16 普通线程矩阵乘，标明输入、启动尺寸、地址前提与预期结果。它们只有设备代码，无主机加载器，未调用编译器或设备；矩阵例子不声称使用 Tensor Core。

## 目标评估

默认 `sm_103a`；可选 `sm_103`、`sm_103f`，CLI 另保留 `sm_89`。目标模式与 ISA 版本分开：选择 B300 不代表本机工具链接受所有 ISA 9.4 形式。

规则 `documented_target_alternatives_v1`：

- 无后缀最低目标按 CC major/minor 比较；架构专属 a 目标要求具体目标匹配，不把 sm_90a 或 sm_100a 自动继承到 sm_103a。
- family 目标要求同 major、minor 不低于下限，当前目标为 f 或 a；基础 sm_103 不据此获得 family 功能。
- 相同 subject 的目标作为可选支持路径归并；弃用后明确排除优先。不同 subject 的条件混合时保留 partial，未解析或缺少依据时保留 unknown。
- 交叉引用尚未展开时不能升级为完整支持。规则按已提取 subject 工作，不是完整语法/类型合法性求解器；查看具体限定符与原文仍然必要。

例如 wgmma 的 sm_90a 条件不覆盖 sm_103a；tcgen05.mma 在默认目标下包含可用路径和不满足的限定形式，保留 partial。不要据条目级状态生成任意变体。

## 查询与界面

`topics` → `get learn_…` → `relations` / `evidence` 是学习入口；指令 `get` 增加 syntax_detail、guide（可为空）、target_assessment。后者始终是本次查询目标；分页摘要不复制全部规则。

网页默认 PTX 全景，主区承担全文阅读，右侧只作随手查。指令速查和官方手册目录仍是可连续滚动的索引；术语、代码查询不改变正文位置。URL 保存后端、目标与主题/指令 ID，JSON 导出当前正文或当前筛选结果。文档依据、原创解释、编译、运行与性能结论始终分开。
