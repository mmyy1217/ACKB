# CCEC 架构支持证据追踪

本轮完成同版本 CANN 包的全量接口静态架构审计，不依赖设备连接。覆盖 5,714 条接口记录、14 个 NpuArch、74 个芯片配置，共 79,996 个判定项。静态声明、源码引用、编译器接受性和运行正确性分别记录。

## 来源与复现

输入固定为 CANN `9.3.0~weekly.20261104.01`。提取前核对版本元数据、23 个资源头文件和 74 个平台配置哈希；安装目录只读。新增 1,608 个 AscendC 头文件均与原始安装包内的 `cann-asc-devkit_9.3.0_linux-x86_64.run` 逐字节核验，结果在 `support-package.json`；只读取嵌套归档，不执行安装脚本。

扫描 basic_api、asc/include、asc/impl/basic_api、simt_api、c_api、utils，解析符号链接并去重。保存 21,361 个名称词法引用、5,274 条 include 记录、宏定义与取消定义、原始条件、文件哈希和行号。4 个非 UTF-8 头文件采用保留字节的 Latin-1 回退，只解析 ASCII 标识符，告警完整保留。系统包含、宏包含和搜索路径未完整解析；不扩展 PTO、高层 API 全集或硬件反汇编。

`support-evidence.json` 是原始证据；`static-support.json` 是绑定其哈希的架构矩阵与缺失宏审计。重新提取后必须重建矩阵，构建网页会拒绝过期矩阵。具体命令见根目录 AGENTS.md。

## 判定口径

以平台配置中的 NpuArch 为已知宏，从含明确架构条件的 include 分支追踪相对包含路径，再结合引用处的预处理条件。目录名称仅用于导航，不生成支持结论。防重复包含宏独立识别，不将未知功能宏当成未定义或零。

| 状态 | 含义 | 950 / 3510 记录数 |
| --- | --- | ---: |
| 架构分支有引用 | 架构选择路径及引用条件可满足 | 2,038 |
| 架构分支条件引用 | 路径或引用仍含未知条件 | 64 |
| 仅通用源码引用 | 有名称引用，但无明确架构选择路径 | 819 |
| 仅声明证据 | 声明条件符合，未找到可用架构引用 | 1,431 |
| 声明条件缺少宏依据 | 声明条件未知，未取得更强源码线索 | 550 |
| 声明条件排除 | 当前宏场景排除该声明 | 366 |
| 声明排除但同名形式有引用 | 当前声明被排除，架构分支仍引用同名形式 | 446 |

这些是名称级源码判定，不是精确重载支持矩阵。引用包含声明和宏体，未解析 C++ 重载、模板、任意控制流或完整翻译单元可达性；跨行分开的名称及括号可能漏记。没有引用不意味着硬件不支持；最后一类也不自动认定源码矛盾，可能涉及其他重载形式。

宏审计记录受影响接口和扫描范围内的条件定义；编译器预定义环境仍未知。`ASCEND_IS_AIC` / `ASCEND_IS_AIV` 块作为核保护线索保存，不推断其他核不支持。CMake 显式 `-D__DAV_C310__` 只作为构建配方，不冒充完整预定义宏集。

## 950 的例子与修正

`copy_gm_to_cbuf_align_v2` 的底层 alias 声明使用 `...`。AscendC 的 dav_3510 搬运实现中有名称调用，处于 `ASCEND_IS_AIC` 块，上游 include 条件为 `__NPU_ARCH__ == 3510`。详情提供声明、引用和架构选择路径三层来源，不将其解释为全部参数形式均支持。

修复 `CCE_AICORE_INTRINSICS_ALIAS` 重复声明保护被当成架构限制的问题后，950 声明条件为符合 3,524、未知 1,378、排除 812；未知减少 1,142 条。原始条件与 ignored_guards 均保留。这组声明计数与上表的源码证据分类属于不同维度。

## 网页与 AI 入口

网页架构面板新增“源码证据”筛选；详情展示当前架构判定、核保护线索、代表性源码路径/行号/哈希及全部 14 个架构。报告展示覆盖与扫描告警，导出携带静态证据。选择源码证据会清空声明条件筛选，避免隐藏“声明排除但同名形式有引用”。

`query.py support` 接受既有 record/symbol/variant 身份及芯片、核目标，返回声明判定、缺失宏、源码判定和路径。`ccec_support.py get` 提供完整引用分页；`matrix` 枚举 74 个芯片配置。`ccec_static.py report` 提供架构汇总，完整宏审计位于矩阵文件。

## 静态边界

本轮没有执行编译或运行验证，`support` 保持 `unverified`；这不影响静态审计完成。仅凭包内源码无法确定的精确类型组合、重载接受性和运行行为明确保留为证据缺口。

已准备的 `ccec_probe.py` 属于未来可选编译工具，不是本轮前置条件，也未执行。若另行授权编译，须遵守远程资源规则、核对工具链哈希，先验证空 kernel 对照；编译失败不自动解释为硬件不支持，不运行生成的 kernel。

## 与唯一 op 层的关系

本文件的 79,996 项矩阵属于历史声明 / 名称引用口径，仅在原始记录中辅助追溯；不作为新主 op 目录的支持矩阵。新层级通过显式 alias 与限定名调用关联，架构只汇总入口声明条件。详见 [op 模型](ccec-ops.md)。
