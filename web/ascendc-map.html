AscendC API 全景与 ACKB 覆盖

先分清编程模型，再看接口抽象，最后追踪具体调用。这里按功能横向对照，帮助你找到正在研究的 API 在整套 Huawei Ascend 开发体系中的位置。

官方分类与本图坐标

SIMD API
官方目录列出基础 API、C API、高阶 API。它们是不同编程抽象，不能排成必经调用链。
SIMT API
线程、Warp、同步、原子与数学等接口；与 SIMD 可共同出现在一个算子中。
Utils API
标准库、平台信息、RTC、日志等；需逐项区分 Device、Host 与编译期。
AI CPU API
面向 AI CPU 执行环境；不归入 AI Core 的 builtin 层。

依据 [S1–S4]。本地图表的“搬运、矩阵、同步”等行是 ACKB 的阅读分类，并非官方四类的逐行复刻。Layout Tensor 来自当前包的 tensor_api 目录，未将其冒充为该版本官方总览中的独立一级分类。

工具与 AI CPU：单独看执行位置

Device 工具
调试输出、断言、部分标准库。属于辅助能力，不能一概放到 Host，也不代表新增硬件 op。
Host / 编译期工具
平台信息、Tiling、运行时编译等服务算子生成与启动。RTC 的调用位置与其生成代码的执行位置需分开。
AI CPU
当前参考 API 列表可见 printf、assert [S4]。不以这份短目录推断 AI CPU 能力全集，也不移植 AI Core 的同步语义。

源码样例告诉我们什么

  1. Layout Tensor → C API：包内矩阵实现调用 asc_mmad [S5]；实验性向量实现调用 asc_not [S6]。证明这些具体位置存在调用，不推广成所有 Tensor API 的唯一实现路径。
  2. 算法库 → 基础接口：Matmul 计算阶段可见 Mmad 调用 [S7]。算法库组合搬运、计算与调度，不能把整个 Matmul 算成一条 intrinsic。
  3. 基础 API / C API → CCEC：当前索引保存封装入口、直连 alias 与 builtin 名称候选。实现可经过不同辅助函数，不能统一标记“1 跳”或断言两套接口绝无交叉依赖。
  4. CCEC → LLVM：这是编译降级关系。普通表达式可生成普通 IR；目标 builtin 的逐项映射仍需独立证据。

ACKB 当前收在哪里

AscendC 高层 API覆盖选定 basic_api 与 simt_api/cpp 函数；C / SIMT API覆盖相应设备接口。两者都属于有界静态索引，不是这两个目录下的所有 API、类型与框架。[S8] 显式排除了部分 op_frame、Tensor、TPipe、类型和工具文件。

CCEC 编程接口、CCEC Builtins和LLVM IR 目标核心继续向下提供分层证据。外部 CCE Dialect 为另一来源体系，PTX 保留独立执行模型。

Layout Tensor、算法库、Host 工具与 AI CPU 尚未建立专项数据库；这里补充定位知识，并未扩展这些 API 的全量提取。这个边界是项目当前的选择，不是“只有前三列才接近硬件”的必然结论。
